# Decisions

- 2026-11-07 Swapdesk enters the focus list as an active project: the owner's order.
- 2026-11-07 Name Swapdesk (open source, GitHub and LinkedIn): the owner's pick; no remote desktop project with that name was found.
- 2026-11-07 Rust + Tauri 2: one core for both systems, native capture, codec and input per OS.
- 2026-11-07 License MIT OR Apache-2.0: the Rust ecosystem's default.
- 2026-11-07 Unattended access (login screen, UAC, lock screen) in v1: the owner's pick; it fixes the process model (service + session helper + user UI) from M0.

- 2026-11-07 D1 Swap opens a new connection with the pinned keys (under 1 s), not the same QUIC connection: a single process for both roles would run the viewer next to SYSTEM code.
- 2026-11-07 D2 v1 extras: session chat and Wake-on-LAN; privacy screen and recording go to Later.
- 2026-11-07 D3 Apple: Developer ID signing, notarization, and the owner requests the Persistent Content Capture entitlement; source builds show the periodic macOS prompt (README says so).
- 2026-11-07 The design is published as a private Artifact for the owner's approval: the owner's yes.

- 2026-11-07 D4 Dependencies: quinn, rustls with ring, mdns-sd, opus, portable-pty, windows-rs, objc2 (and its framework crates), Tauri 2 with the NSIS installer, xterm.js, serde, tokio, proptest. Any new third-party crate goes back to the owner.
- 2026-11-07 D4b No openh264: Cisco's license requires a separate download to the user's device with a user toggle; Windows uses Media Foundation only (NVIDIA, Intel or the Windows software MFT), macOS uses VideoToolbox.
- 2026-11-07 D5 Pairing compares codes: both screens show the same 6-digit code derived from a commitment exchange (ZRTP-style SAS, RFC 6189) and the user confirms "match" on both; no Rust PAKE crate is audited.
- 2026-11-07 Design round 1 rejected: "acceptable but ugly and disorganized"; redesign with the frontend-design skill (colors, buttons, alignment, everything).
- 2026-11-07 Design round 2 approved: one shell (device sidebar + detail), pair strip as the one signature element, Instrument Sans, blue #3346D3 only for link and actions, green only for online, red only for disconnect and forget. The approved boards are in docs/design/.
- 2026-11-07 D6 The service/daemon owns every LAN socket in both roles; the viewer's media reaches the UI over local IPC (private key stays in the service, no Local Network prompt on macOS). If B1 fails through the IPC hop, the question returns to the owner.
- 2026-11-07 D7 Granting UNATTENDED or ADMIN_TERMINAL requires a local administrator.
- 2026-11-07 D8 The incoming-connection prompt may widen or narrow the stored grants for that session only (never UNATTENDED or ADMIN_TERMINAL).
- 2026-11-07 D9 The owner asks for an audit of every dependency: keep only what is really needed; the software must be extremely fast and optimized. Vite + TypeScript, libc and the hand-written codec wait on that audit.
- 2026-11-07 D10 Any local account on the viewer machine may connect with the grants other machines gave it, but using UNATTENDED or ADMIN_TERMINAL on another machine requires a local administrator on the viewer side.
- 2026-11-07 D11 Prompted sessions inject input with the logged-in user's token; elevated windows and UAC are controllable only in UNATTENDED sessions (granted by an administrator).
- 2026-11-07 D12 Pairing requires both users to open "Parear" within the last 2 minutes; unsolicited pairing is ignored. The "Falta você" nudge is removed.
- 2026-11-07 D13 In UNATTENDED sessions, terminal and files of a user other than the one who granted access ask that user first; screen and control proceed without asking.
- 2026-11-07 D14 Minimal dependency list approved (docs/research/dependencies.md, section 6): own ConPTY/openpty instead of portable-pty, TypeScript-only frontend (moot if D17 drops the webview), libc on macOS, the whole objc2 family, serde_json only in the app, own file pickers. Dropped: portable-pty, aws-lc-rs, smol, rustix, postcard, Vite.
- 2026-11-07 D15 Panics: the service/daemon builds with unwind and isolates a panic to the affected session; UI and helpers use panic = abort and the service restarts them.
- 2026-11-07 D16 Audio: Opus through libopus; if it does not build, the pure-Rust opus-rs. With audio off nothing is captured or sent.
- 2026-11-07 D17 The owner rejects the WebView2 memory cost (about 140 MB) and wants a native interface instead of Tauri. The way (native per OS vs a Rust GPU-rendered toolkit without a webview) is decided after the measured comparison in docs/research/ui.md.
- 2026-11-07 Re-pairing when one side forgot: a full compare-codes ceremony may replace the old key, logged as "chave substituída". Defaults kept: audit 90 days (sessions 10 MiB, network 2 MiB), lockout 15 min, per-session caps 4 terminals, 8 transfers, 500 chat messages.
- 2026-11-07 D18 Native interface on each OS (docs/research/ui.md): Windows with Win32 + DirectComposition + Direct2D/DirectWrite and the AccessKit adapter; macOS with AppKit through objc2; state, strings and design tokens in a shared Rust crate. Tauri, WebView2, serde in the UI API, TypeScript and xterm.js leave the project. Measured: 28 MB, 0 idle CPU, zero-copy video under the floating toolbar.
- 2026-11-07 D19 One Rust terminal-emulation crate is approved for the terminal panel; the smallest that works is chosen in stage 20 (vte or similar) and recorded here. Picked 08/11: `vte` 0.15.0 (Apache-2.0 OR MIT, the parser alone; crates.io read 08/11): the grid, scrollback and selection are written in `swapdesk-termview`. It brings two transitive crates, `arrayvec` 0.7 (MIT OR Apache-2.0) and `memchr` 2 (Unlicense OR MIT), part of the same approval.
- 2026-11-08 D20 Every screen applies the owner's performance study (DESEMPENHO-WEB.md), translated to the native app as SPEC "Responsiveness rules" R-UI-1 to R-UI-12; measured, not assumed.
- 2026-11-08 D21 Displays on an NVIDIA adapter encode through NVENC directly (nvEncodeAPI64.dll from the driver, loaded at runtime, hand-written bindings, no new crate; NVIDIA header license MIT-style per docs/research/windows.md 3d), because the NVIDIA H.264 MFT cannot be activated on this PC; other adapters keep Media Foundation (D4b otherwise holds). This PC: DISPLAY1 on Intel (2560x1600, 150%), DISPLAY5 on NVIDIA (2560x1440, 100%).
- 2026-11-08 D22 Smart App Control: no paid option (no paid certificate, no paid signing service). Stage 31 researches only free paths, each checked on a primary page then: free code signing for open-source projects (e.g. SignPath Foundation, to verify), the Microsoft Store for an MSIX signed by Microsoft (free individual registration, to verify), and documenting build-from-source; the owner picks.
- 2026-11-08 D23 Publication: today's release is a labelled Windows preview (v0.1.0-preview: zip and installer, README states what is proven and what is not: two machines and macOS are not). The public history is rebuilt as one Conventional commit per area, without the internal files (CLAUDE.md, docs/ACTIVE-PLAN.json, docs/PLAN-v1.md, docs/reviews/, spikes/, test-results/), which stay local only (owner's choice: no off-disk backup of them). From then on: main is protected (pull requests only, squash, linear history, no force push); work goes on `<type>/<slug>` branches, one complete and tested change per pull request with a Conventional title; releases are tags `v0.x`.
- 2026-11-08 D24 Mac unattended access after the M0-mac probe (macOS 27.2: no capture at the login window, no injected input at the login window or while locked): in v1 the Mac hosts only a logged-in, unlocked session, prompted or unattended; the login window and remote unlock are out of v1 and documented as an Apple limit. Windows keeps full unattended access. Stage 27 shrinks to documenting the limit (and re-testing `__CGPreLoginApp` and the CGDisplayStream fallback when convenient).
- 2026-11-08 D25 Mac signing stays free (D22): the next Mac run tests whether a self-signed code-signing certificate keeps the TCC grants (Screen Recording, Accessibility, Input Monitoring) across rebuilds; if not, ad-hoc signing stays and the README warns that each update asks for the grants again.
- 2026-11-08 D26 The objc2 family is approved for every macOS crate (owner, 08/11): `objc2` 0.6.5, `block2` 0.6.2, `dispatch2` 0.3.1 and the 0.3.2 framework crates (`objc2-foundation`, `-app-kit`, `-quartz-core`, `-core-foundation`, `-core-graphics`, `-core-media`, `-core-video`, `-video-toolbox`, `-av-foundation`, `-audio-toolbox`, `-core-audio`, `-core-audio-types`, `-security`, `-system-configuration` (added 08/11 for the physical-interface check), and later `-screen-capture-kit`, `-service-management` for stage 24). Licenses MIT, or Zlib OR Apache-2.0 OR MIT (crates.io read 08/11). Each is a `[target.'cfg(target_os = "macos")'.dependencies]` entry with only the framework features used.
- 2026-11-08 D27 Priority (owner, 08/11): the Mac controlling this Windows PC comes first. The first Mac viewer slice embeds `ServiceCore` in the app process, with `swapdesk-net-mac` (getifaddrs, physical Wi-Fi/Ethernet only) and `swapdesk-secret-mac` (identity and trust files protected by the user's login keychain) brought forward from stage 24, so the app owns its LAN sockets until the stage 24 daemon takes them (ARCHITECTURE "on macOS no agent or app touches the LAN" holds from stage 24). Revert: stage 24 moves `ServiceCore` into the daemon and the app talks to it over the Unix socket.
- 2026-11-08 D28 Minimal, audited dependencies (owner, 08/11; replaces the earlier 'zero third-party dependencies' goal). `quinn`, `rustls` and `ring` stay for good: they are audited and widely deployed, the transport costs 0.99 ms and `ring` is per-CPU assembly, so a rewrite gains no speed, and home-made TLS or cryptography is only safe after years of independent review. The supply chain is controlled instead: `cargo-deny` (advisories, licenses, sources, duplicates) and `cargo-vet` in CI, every build `--locked`, Dependabot for cargo and GitHub Actions; vendoring (`cargo vendor`) only if its measured size is one the owner accepts, since the `windows` crate alone is tens of MB of source. The project's own code covers only small domain pieces where it pays (`vte`, possibly `mdns-sd`) besides what already is its own (wire codec, terminal model, NVENC FFI). D9, D14, D19 and D26 stand.
- 2026-11-08 D29 The macOS program is its own crate, `swapdesk-app-mac` (library `swapdesk_app_mac`, binary `swapdesk-app-mac`, installed by `scripts/mac/build-app.sh` as `Swapdesk.app/Contents/MacOS/Swapdesk`), not a `cfg(target_os = "macos")` half of `swapdesk-app`; the OS-free half of the viewer pipeline moved from `swapdesk-app` into `swapdesk-app/src/shared` (`mailbox`, `feedback`, `cursor`, `audio`, `out`, `down`; the `viewer::*` paths re-export them) so both programs use one copy. Why: `swapdesk-app` forbids `unsafe` and is built on the Windows PC, while the Mac app needs the one `unsafe` of this lane (a decoded `CVPixelBuffer` handed to the main thread) and `atexit`, and Apple-only dependencies; a platform crate keeps `unsafe_code` allowed where the other app keeps it forbidden. Consequences: the cargo binary is not named `Swapdesk` (two bins of that name write the same `Swapdesk.exe` in a shared target folder on Windows and the build fails with LNK1104); the app-mac crate builds on Windows without its macOS modules, so the Windows gate type-checks and tests its cross-platform half (`cli`, `service`, `pipe`, `handoff`, `layout_state`, `prefs`, `trace`); its `Cargo.lock` entry adds no third-party crate (the objc2 family of D26, including `objc2-quartz-core` and `objc2-core-foundation` as direct dependencies). Revert: merge the crate back into `swapdesk-app` behind `cfg`, at the cost of the `unsafe` exception.

- 2026-11-08 D30 Viewer shortcuts (owner, 08/11, design round 3): Windows: release the keyboard Ctrl+Alt (configurable: Ctrl+Alt, right Ctrl, Ctrl+Alt+Shift), show the session bar Ctrl+Alt+B, full screen F11, send Ctrl+Alt+Del with Ctrl+Alt+End, disconnect Ctrl+Alt+Q; macOS: Control+Option in place of Ctrl+Alt and Control+Command+F for full screen. They stay with Swapdesk even when "Capturar atalhos do sistema" is on, and are listed in Settings and in the toolbar tooltip.

- 2026-11-08 D31 The Mac app keeps its secrets (identity, trust store, settings) as files, mode 0600 in a 0700 `secrets` folder under `~/Library/Application Support/Swapdesk`, instead of login-keychain items (owner, 08/11: every rebuild re-asked permissions and blocked the app). Why: the login keychain ties an item's "Always Allow" to the exact binary of a self-signed app, so each rebuild or update showed a keychain prompt and the app waited at start. Cost: any process of the same user can read the files, the same reach as a keychain item set to allow every app and as DPAPI user scope on Windows. Items already in the login keychain are read once and copied (one last prompt). The stage 24 root daemon keeps root-owned secrets (C5.2). Revert: `SecretLocation::login` back to `KeychainLocation::Login`.
- 2026-11-09 D32 The Mac hosts from inside Swapdesk.app in v1 (owner, 09/11), extending D27: no root daemon and no Aqua agent. The app registers itself as a login item (`SMAppService.mainApp`, which needs no approval; a daemon would wait for an admin's approval in Login Items, maybe again after each self-signed rebuild, R13) and stays in the menu bar when its window closes, so it keeps hosting. Out of v1 on the Mac: the administrator terminal (F-TERM-02 as root), a root-held device key (the key stays a user file, D31), the LoginWindow agent (already out by D24). Revert: build the daemon and agent of SPEC F-SYS-02 and move `ServiceCore` there.
- 2026-11-09 D33 Version 1.0.0 ships on 09/11 with what is proven (owner, 09/11): Windows to Windows, the Mac viewing and controlling a Windows host, Windows viewing and controlling the Mac host from inside the app (D32), with screen, audio, mouse, keyboard and pairing. Before the tag: the Mac login item and menu bar, the relay and viewer queue fix, green CI, a focused security review (pairing, guard, IPC ACLs), README and docs true to this scope, release assets (Windows zip, Mac app). Moved to v1.1 and listed in the README roadmap: cross-OS swap, terminal, files and clipboard proofs; Windows unattended at the login, UAC and lock screens; the 8 h soak; display switching proof; the frame-path and text-layout performance work; the round 3 screens, texts and accessibility pass; the Windows tray and first-run flow; installers with uninstall entry; screenshots, PERFORMANCE.md, the VM proof, Linux CI and fuzzing, the launch page. Revert: tag a 1.0.0 only after those stages close.
- 2026-11-09 D34 Renaming a paired device and three host-bar defects join 1.0.0 before the tag (owner, 09/11). The rename is a local alias: it overwrites the paired device's name in this machine's trust store and changes nothing on the other machine. Swap stays offered only between two machines of the same OS, since swap across Windows and macOS is v1.1 (D33). Revert: ship the rename in a later version.
- 2026-11-09 D35 The main window gets a home screen ("Início") and a narrower sidebar, in 1.0.0 (owner, 09/11). The sidebar holds navigation and the device lists only (Início, Pareados, Na rede, Ajustes) at about 280 px. Início opens with this computer's name and state, with the network line ("Só na rede local: Wi-Fi, <IPv4>") at the top right, then cards: Parear (the pairing button and the add-by-address field) and Atividade recente (with "Ver tudo"). Later features join as new cards. Revert: the round 3 sidebar.
- 2026-11-09 D36 Roadmap after 1.0 (owner, 09/11). 1.1 adds a 10 to 15 s demo loop at the top of both READMEs (pairing, the other screen, the mouse, a swap), recorded in a real session on the PC and the Mac with the owner at both; a GIF if it stays small enough to load fast on the README page, otherwise a short MP4, checked on the published page. Access from outside the LAN and device groups are a later direction with no version: LAN-only is the product's main promise and is enforced in code, so a mode beyond the LAN is opt-in, off by default, and each step starts with a design note and a threat model. The first step considered is a user-chosen VPN interface (WireGuard, Tailscale, ZeroTier) the guard may approve, with pairing and TLS unchanged and no server to run; a relay or NAT traversal comes only after that, and a hosted relay is the owner's decision on cost and abuse. The 1.x texts drop "never" and "permanently" for beyond-LAN access and keep LAN-only as what 1.x does. Revert: restore those words and drop the later direction from the README.
- 2026-11-09 D37 One renderer for both systems (owner, 09/11). The Mac app looked nothing like the Windows app and the design boards because it built its screens from AppKit controls (buttons, stack views), whose sizes, colours and corners are macOS's own. The screens the Windows shell paints (main window, viewer and its drawer, files, dialogs, banner) move to a shared crate over a painter trait; Windows keeps its Direct2D painter and the Mac gets one on CoreGraphics and CoreText with the same embedded font. Text inputs stay native controls placed in the slots the screens report (as on Windows), hit testing uses the widget rectangles the screens report, and accessibility comes from the shared tree (`swapdesk_ui::a11y`) exposed as AppKit accessibility elements. Only the window chrome is each OS's own. No new third-party crate. Revert: the Mac shell's AppKit screens are in the history before this change.
