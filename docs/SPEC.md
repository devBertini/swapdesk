# Swapdesk: spec, version 1

Current truth for v1. Contracts: `docs/PROTOCOL.md` (C1), `docs/CONTRACTS.md` (C2 to C7). Why: `docs/DECISIONS.md` (D1 to D19). Evidence: `docs/RESEARCH.md` and `docs/research/`. Every flow below enters `docs/FLUXOS.md` before its code.

Marks: **UNPROVEN** = no primary page settles it yet, its stage proves it. **GUESS** = a design number or inference to confirm in its stage. Dependencies are the minimal list of D14 (`docs/research/dependencies.md` section 6) minus what D18 removed; the interface is native per OS (D18, `docs/research/ui.md`).

## Purpose

- For: the owner at home, with one MacBook and one Windows notebook on the same LAN; later anyone who builds the open-source repository.
- Problem: AnyDesk and TeamViewer go through the cloud. Swapdesk does screen, system audio, mouse, keyboard, terminal, files, clipboard, chat, Wake-on-LAN and unattended access between the two machines, in all four directions, with nothing leaving the LAN.
- Success: the owner uses it instead of AnyDesk at home for a month, within the budgets below, and "Request swap" inverts who controls whom in under a second.

## Flows

Roles: the **viewer** controls, the **host** is controlled. Both machines can be either. Permission names are those of C5 (`VIEW`, `CONTROL`, `AUDIO`, `TERMINAL`, `ADMIN_TERMINAL`, `FILES`, `CLIPBOARD`, `UNATTENDED`). A **local administrator** means a UAC-elevated connection on Windows or an Authorization Services admin right on macOS, checked by the service/daemon (CONTRACTS.md C2.3), never group membership alone.

| ID | Flow | Criteria |
|---|---|---|
| F-FIND-01 | Discover devices | When two Swapdesk machines are on the same LAN, Swapdesk shall list the other within 5 s (GUESS) with name, OS and online state, through DNS-SD `_swapdesk._udp`, without any traffic leaving the subnet. When a device stops answering, Swapdesk shall show it as asleep or offline within 10 s (GUESS). |
| F-FIND-02 | LAN guard | When an interface is virtual (WSL, Hyper-V, Docker vEthernet), a VPN or a tunnel, Swapdesk shall not announce, browse or accept on it. When a connection arrives, Swapdesk shall refuse it before the TLS handshake unless the remote address is on-link in the subnet of the approved interface it arrived on (`Incoming::local_ip()`), and is not loopback or one of this machine's own addresses. When a QUIC packet is sent, Swapdesk shall send it with IP TTL 1 (mDNS keeps TTL 255, link-local multicast). |
| F-FIND-03 | Manual address | When the user types an IPv4 address on-link, alone or followed by `:port` when the other computer's Swapdesk listens on another port than the default, Swapdesk shall try it as a device; when the address is off-link, loopback or this machine's own, Swapdesk shall refuse it and say why. |
| F-FIND-04 | Network notices | When Windows marks the active network Public or the firewall blocks inbound traffic, Swapdesk shall show the "rede Pública" notice with a button to the network settings. When the macOS service is not yet approved in Login Items, or a macOS permission the host needs is missing, Swapdesk shall show which one and a button to System Settings. |
| F-PAIR-01 | Pair by comparing codes | When both users opened "Parear" within the last 2 minutes (D12), Swapdesk shall show the same 6-digit code on both screens (commitment exchange, PROTOCOL.md section 3) and pin the peer's key only after both users press "Os códigos são iguais"; neither screen shows whether the other side confirmed. A new device starts with no grants here: every session with it prompts until the host's user grants more. When a pairing attempt arrives while this machine is not in pairing mode, Swapdesk shall ignore it without an answer or a prompt. |
| F-PAIR-02 | Mismatch and lockout | When a user presses "São diferentes", the comparison times out (120 s, GUESS), the commitment does not open, or the attempt ends in any way after the responder sent its nonce without both confirmations, Swapdesk shall pin nothing, count a failed attempt (written to disk before the nonce is sent) and log it. When 3 attempts fail within 15 minutes, the host shall refuse pairing for 15 minutes (GUESS) and say so; paired devices keep working. |
| F-PAIR-03 | Unknown device and resumption | When a key that is not pinned tries a session, Swapdesk shall refuse it in the TLS handshake, log it (rate-limited) and raise the "aparelho desconhecido" alert in Atividade with "Bloquear <address>". When a peer offers TLS session resumption or 0-RTT, Swapdesk shall issue no tickets and run a full handshake, and shall check the peer's key against the trust store again after every handshake before any stream is accepted. |
| F-PAIR-04 | Forget | When the user forgets a device, Swapdesk shall delete its key and grants, end any session with it, invalidate its resume tokens, and require a new pairing. |
| F-PERM-01 | Grants per direction | When the host's user edits what a device may do here, Swapdesk shall store it for that device and direction only and show the other direction as read-only, decided by the other machine. When the change grants `UNATTENDED` or `ADMIN_TERMINAL` and does not come from a local administrator (D7), the service shall refuse it; the UI offers to elevate but never decides. |
| F-PERM-02 | Enforcement | When a viewer asks for anything not granted for this session, the host shall refuse it with `NOT_PERMITTED` and do nothing. When the host's user revokes a grant during a session, the host shall stop that feature within 1 s and invalidate the session's resume token. |
| F-PERM-03 | Admin use on the viewer side | Any local account on the viewer machine may connect with the grants other machines gave this machine (D10), and may enter without a prompt where the host stored `UNATTENDED` for it: the viewer asks for that entry toward a host it knows to be 1.1 or newer, never toward a 1.0 host (D44). What reaches the machine level of another computer still needs a local administrator of the viewer's machine: when a viewer-side user who is not one tries to open an administrator terminal, the viewer's service shall refuse it. |
| F-SESS-01 | Incoming request | When a paired device without `UNATTENDED` asks for a session and someone is at the host, the host shall show the request with per-session choices preset to the stored grants, which the host's user may widen or narrow for this session only (never `UNATTENDED` or `ADMIN_TERMINAL`, which need a local administrator in Permissões), and auto-decline after 20 s. When nobody is at the host, the host shall refuse at once with `NOBODY_PRESENT`. "Só deixar ver" shall grant `VIEW` only. When the host locks, logs off or shows UAC during a session without `UNATTENDED`, the host shall pause video and drop input until its desktop returns (`HostState`). |
| F-SESS-02 | Unattended entry | When a device holding `UNATTENDED` connects and asks for it, the host shall let it in without a prompt and log "Entrou sem perguntar". A viewer of 1.1 or newer enters with the stored permissions it asked for except `UNATTENDED` and `ADMIN_TERMINAL`: its session pauses at the login screen, the lock screen and UAC like a prompted one, until it elevates (D44). A 1.0 viewer has no such step and gets the whole grant, including at the login screen, the lock screen and UAC. When such a session asks for the terminal or files while a user other than the one who granted `UNATTENDED` is logged in, the host shall ask that user first (D13; nobody present = refused); screen and control proceed without asking. |
| F-SESS-03 | Being controlled | When a session is active, the host shall show the "Sendo controlado" banner with the peer, the time, "Inverter" and "Desconectar"; "Desconectar" shall end the session within 1 s and invalidate its resume token. When the session ends and "Bloquear ao terminar" is on, the host shall lock its screen. |
| F-SESS-04 | Activity log | When a pairing, session, swap, transfer, terminal, quick action, refusal or grant change happens, Swapdesk shall append one entry to the local audit log; entries from unauthenticated peers shall be rate-limited with an "N suppressed" summary and kept apart from session and grant entries; Atividade shall list it and "Exportar registro" shall write it, from the UI with the user's rights, to a file the user picks. |
| F-VIEW-01 | See the screen | When a session starts, the viewer shall show the host's display within 1 s (GUESS) at up to 1080p60, inside budgets B1 and B2. |
| F-VIEW-02 | Displays and scale | When the host has several displays, the viewer shall list them and switch on "Escolher tela" without reconnecting; Fit, 1:1 and scroll shall work with mixed DPI, Retina and negative virtual-desktop coordinates. When a display is added, removed or changes mode, the viewer shall update within 2 s (GUESS). |
| F-VIEW-03 | Quality and overlay | When the user picks Automática, Texto nítido or Movimento fluido, the host shall change the encoder settings (Texto nítido = 4:2:0 at high bitrate and lower frame rate); "Mostrar latência e quadros" shall show the measured latency and fps. |
| F-VIEW-04 | Loss recovery | When frames are lost or a stream is reset, the viewer shall request a keyframe and show a clean picture again within 500 ms at 1% injected loss. |
| F-INPUT-01 | Physical keys | When the keyboard mode is "Teclas físicas", the viewer shall send HID usages and modifiers and the host shall press the same physical keys (C4 tables), including AltGr without a stray Ctrl, the ISO `§`/`` ` `` swap on Mac, and "Trocar Ctrl e Cmd no Mac". |
| F-INPUT-02 | Text mode | When the mode is "Texto", or "Automático" and the two keyboard layouts differ, the viewer shall send printable characters as Unicode text and shortcuts as physical keys, so ABNT2 to US types the same characters. |
| F-INPUT-03 | Pointer and wheel | When the viewer moves, clicks or scrolls, the host shall place the pointer at the same normalized point of the selected display and apply buttons and high-resolution wheel deltas. |
| F-INPUT-04 | System keys and integrity | When "Capturar atalhos do sistema" is on, the viewer shall send Alt+Tab, Win/Cmd and similar keys to the host instead of its own OS. In a prompted session the Windows host shall inject with the logged-in user's medium-integrity token, so elevated windows and UAC are not controllable (D11); only an `UNATTENDED` session injects as SYSTEM and may send Ctrl+Alt+Del, which the service performs through `SendSAS`. When the viewer loses focus, it shall release every held key and button on the host. |
| F-INPUT-05 | View only | When the session is view-only (no `CONTROL`, or "Assistir"), the host shall drop every input event and the viewer shall send none. |
| F-AUDIO-01 | System audio | When `AUDIO` is granted and audio is on, the viewer shall play the host's system audio (Opus 48 kHz) inside budget B3; when the host mutes, the viewer shall play silence and show it. When audio is off, the host shall capture and send nothing (D16). |
| F-SWAP-01 | Swap accepted | When either user presses "Inverter" and the other accepts within 20 s, Swapdesk shall close the session and open the reverse one on a new connection with the pinned keys, with the grants each side already gave, inside budget B4. |
| F-SWAP-02 | Swap refused | When the asked user declines, 20 s pass, nobody is at the asked side, or the side about to be controlled has not granted `CONTROL` to the other, Swapdesk shall leave the current session unchanged and say why; the last two shall be refused at once, without a prompt. |
| F-TERM-01 | Terminal as the user | When `TERMINAL` is granted and the viewer opens Terminal, the host shall start the user's shell as the logged-in user (never SYSTEM or root) in a PTY; resize and close shall work. When no user is logged in, the host shall refuse unless an administrator terminal is asked for and allowed. At most 4 terminals per session (GUESS). |
| F-TERM-02 | Administrator terminal | When `ADMIN_TERMINAL` is granted on the host and the viewer-side user is a local administrator (F-PERM-03), the host shall start a shell as SYSTEM in session 0 (Windows) or as root from the daemon (macOS), never on the user's desktop, labelled as such in the panel, and log it. |
| F-ACT-01 | Quick actions | When `CONTROL` is granted, "Bloquear a tela", "Suspender", "Reiniciar" and "Monitor de Atividade" (Task Manager on Windows) shall run on the host and report success or the error. Task Manager and Activity Monitor are launched only as the logged-in user and refused when nobody is logged in; with nobody logged in, lock, sleep and restart are system calls from the service and start no process. |
| F-FILE-01 | Transfers with resume | When `FILES` is granted, files dragged or chosen shall go to the folder the receiving side's user chose, read and written by a process of the logged-in user (never by the service), with progress; when the link drops mid-way, the transfer shall pause and "Retomar" (or the reconnect) shall continue from the last verified byte; a finished file shall match its SHA-256. When a name holds `..`, `/`, `\`, `:` or a reserved device name, or a stream exceeds the offered size, the receiver shall refuse it. A viewer shall accept a file from the host only as the answer to its own request. At most 8 transfers per session at once (GUESS). |
| F-FILE-02 | Remote folder | When `FILES` is granted, the viewer shall list a folder of the host (as the logged-in user), change folder, and download a file from it into a folder the viewer's user chose. |
| F-CLIP-01 | Clipboard | When `CLIPBOARD` is granted and sync is on, text and images copied on either side shall be available on the other within 1 s (GUESS); content marked concealed by a password manager shall never be sent. |
| F-CHAT-01 | Chat | When either side sends a message during a session, the other shall show it with its read state; messages shall vanish when the session ends; at most 500 messages are kept per session (GUESS). |
| F-WAKE-01 | Wake-on-LAN | When the user wakes an asleep paired device, Swapdesk shall send the magic packet with TTL 1 to the broadcast of the approved local interface whose subnet holds the device's last address, to the MACs it reported after pinning, show "Acordando" and connect when it appears, giving up after 60 s. Windows targets are promised; MacBook targets are best effort (probe P10). |
| F-NET-01 | Reconnect | When the connection is lost (network drop, sleep, IP change), the viewer shall show "Reconectando" with the attempt number and resume the session without a new prompt, inside budget B5, with no more than the grants the session had that are still stored. A resume token is single-use, bound to the device and valid only after a connection loss; "Desconectar", `Bye`, a grant change, Forget and lock-on-end invalidate it. When an unattended host reboots, the viewer shall reconnect through `UNATTENDED`. |
| F-UNAT-01 | Windows secure desktop | When the Windows host shows the login screen, the lock screen or a UAC prompt, the viewer in an `UNATTENDED` session shall see it and type into it (SYSTEM injector, D11). |
| F-UNAT-02 | macOS lock and login window | When the macOS host (14.4 or later) is locked or at the login window, the viewer with `UNATTENDED` shall see and control it within what probe P4 to P6 allowed; FileVault pre-boot is out of reach and documented. |
| F-SEC-01 | Never logged | Swapdesk shall never write to any log the private key, pairing nonces, the TLS exporter output, the SAS or its hash input, resume or swap tokens, terminal bytes, text input, clipboard, chat or file contents; the service's trace log lives under the C5 folder ACL. |
| F-UI-01 | Interface | Every approved screen (docs/design) shall exist as a native window on each OS (D18: Win32 + DirectComposition + Direct2D/DirectWrite on Windows, AppKit on macOS), in pt-BR and en, light and dark following the system theme live, sharp at per-monitor DPI (per-monitor v2 on Windows, Retina on macOS). Screen readers shall read and operate every control: Narrator through the AccessKit adapter (UI Automation) on Windows, VoiceOver through NSAccessibility on macOS; text inputs are native controls (IME). The shells also show three states the design lacks: the D13 consent card ("<device> quer abrir o terminal / os arquivos desta conta"), the elevation step before an admin-only change or use (UAC on Windows, the admin password on macOS), and "Parear este computador" with a 2-minute countdown (D12). The pairing screen drops "Confirmado no ... Falta você" (D12). |
| F-SYS-01 | Windows install and uninstall | When the installer runs, it shall install per machine under `%ProgramFiles%` (never per user), register the service, add the firewall rules (Private and Domain, LocalSubnet), and set `SoftwareSASGeneration` after saving its old value; the service shall refuse to start helpers from a user-writable path. Uninstall shall remove all of it, restore the value, delete only the files it knows, and leave nothing behind. |
| F-SYS-02 | macOS install | When the app first runs, it shall register the daemon and the Aqua agent through `SMAppService`, guide the approval, and, when unattended access is turned on, have the daemon write the LoginWindow agent plist; at start the daemon shall check that its bundle is root-owned and validly signed; turning unattended off and uninstalling shall remove them. |
| F-SYS-03 | Fault isolation | When a panic happens in the service or daemon while it handles one session, Swapdesk shall end that session only, log it, and keep the other sessions and the network up (unwind build, D15). When a helper, an agent or the UI panics, it shall abort; the service/daemon restarts helpers and agents, and sessions survive a helper restart. |
| F-UI-02 | One interface on both systems (D37) | When a screen is drawn on Windows or macOS, Swapdesk shall paint it from the same shared screens, so layout, spacing, type, colours, texts and behaviour are the same on both and only the window chrome is the system's own. On macOS the windows shall take clicks, scrolling and the keyboard on the painted controls, place native text fields in the slots the screens report, and expose every drawn control to VoiceOver from the shared accessibility tree; every effect a screen asks for (file and folder pickers, menus, logs, open at login) shall do on macOS what it does on Windows. |
| F-XCLIP-01 | Clipboard between Windows and Mac | When `CLIPBOARD` is granted and sync is on in a session between a Windows machine and a Mac, text and images copied on either side shall be available on the other, in both session directions. |
| F-XFILE-01 | Files between Windows and Mac | When `FILES` is granted in a session between a Windows machine and a Mac, a file sent either way shall arrive whole under the same name, cancel when asked and resume after a dropped link, in both session directions. |
| F-XTERM-01 | Terminal and quick actions between Windows and Mac | When `TERMINAL` is granted in a session between a Windows machine and a Mac, the viewer shall open the host's shell as the host's logged-in user, resize it and close it, and with `CONTROL` run a quick action, in both session directions. |
| F-XSWAP-01 | Swap between Windows and Mac | When a swap is accepted in a session between a Windows machine and a Mac, Swapdesk shall open the reverse session with the pinned keys inside budget B4, with no new pairing, starting from either direction. |
| F-XCHAT-01 | Chat between Windows and Mac | When either side sends a chat message in a session between a Windows machine and a Mac, the other shall show it with its read state, in both session directions. |
| F-XNET-01 | Reconnect between machines | When the Wi-Fi link between two machines drops for 10 s during a session and returns, the viewer shall show the first frame again inside budget B5 without a new prompt. |
| F-XUPG-01 | Upgrade from 1.0 and mixed versions | When a newer version is installed over 1.0, Swapdesk shall keep the device identity, the paired devices with their grants and the settings. When one machine runs 1.0 and the other a newer 1.x, a session with screen, mouse and keyboard shall work in both directions. |
| F-NET-02 | Wire compatibility inside a major | When a peer announced protocol minor N, Swapdesk shall send it only message types and enum values that exist in minor N, and shall decode everything a peer of an older minor sends (PROTOCOL.md section 1). |
| F-FILE-03 | Free space and names across systems | When a file is offered and the receiving folder's volume has less free space than the file needs, the receiver shall decline it and say why, before writing anything. When a name differs from an existing one only by Unicode normalization or by letter case on a file system that treats them as equal, the receiver shall save it under a new name and never overwrite. When macOS has not granted access to the receiving folder, the Mac shall say so and show where to grant it. |
| F-VIEW-05 | Still-screen refinement | When the host's picture has not changed for 400 ms (GUESS), the host shall send one refined frame so that still text is sharp, and nothing more until the picture changes; on a Windows host and on a Mac host. |
| F-VIEW-06 | Scale to the window and negotiated frame rate | When the quality is Automática or Movimento fluido and the viewer's window shows the picture smaller than the host's display, the host shall encode at the size shown and follow the window when it changes; Texto nítido and 1:1 shall stay at the native size. When both sides support more than 60 frames per second, Movimento fluido shall run at the lower of the two displays' refresh rates, up to 120. |
| F-VIEW-07 | HEVC with H.264 as the fallback | When both machines have a hardware HEVC encoder and decoder and both speak a protocol minor that knows HEVC, the session shall use HEVC; otherwise it shall use H.264, and the overlay shall name the codec in use (D39). |
| F-VIEW-08 | Lost graphics device | When the viewer's graphics device is lost (driver reset, adapter removed), the viewer shall create it again, ask for a keyframe and show the picture without ending the session. |
| F-VIEW-09 | Bitrate ramp | When a session starts on a link without loss, the bitrate shall reach the session's ceiling within 8 s (GUESS); at 1% loss and 20 ms of jitter it shall settle without oscillating: after congestion it returns to a rate just under the one that met it and stays there, trying one small step above it only after a long calm. A session that arrives over Ethernet starts at 40 Mbps, any other at 20 Mbps (GUESS). |
| F-VIEW-10 | Monitors changed on the host | When the host's monitors change while its service runs (one plugged in or unplugged, the lid closed, another primary), a session started afterwards shall show the picture of a display that exists and its pointer shall land on that display, without restarting the service. |

## Responsiveness rules (every screen)

From the owner's performance study (`~/Documents/Projetos/DESEMPENHO-WEB.md`, D20), translated to a native app. Measure before changing: each rule is proven by a test or a trace line, never assumed.

- **R-UI-1 Placeholder shapes:** a screen whose data takes over 100 ms (device discovery, remote folder listing, Atividade, connecting) shows its layout with neutral placeholder blocks; under 100 ms it shows nothing in between, so nothing flashes. Layout never jumps when data arrives.
- **R-UI-2 Optimistic changes:** switches and choices (grants, settings, audio, clipboard sync) change on screen at once and are sent to the service; a refusal reverts them and says why. Never for pairing confirmation, admin grants or Forget, which wait for the service.
- **R-UI-3 No duplicate requests:** `UiBackend` merges identical in-flight commands into one; the device list, grants, settings and activity are cached in `UiState` and refreshed by service events, not by polling; the service answers "unchanged" with a version number instead of resending.
- **R-UI-4 Debounce:** typed filters and the manual address field act 150 ms after the last key; chat sends on Enter only.
- **R-UI-5 Draw in pages:** long lists (Atividade, remote folders, transfers, terminal scrollback) draw only the visible rows plus a margin; the service sends folder listings and activity in pages.
- **R-UI-6 Parallel start:** at launch the UI asks for the device list, settings, identity and activity at the same time; the window appears with placeholders before any answer.
- **R-UI-7 Timeouts everywhere:** every IPC call and every network operation has a timeout and a visible failure (C6 replies and PROTOCOL timers); nothing waits forever.
- **R-UI-8 Background work:** pairing, transfers, wake, exports and reconnects run off the UI thread and report progress as events; the UI thread only draws and handles input (no blocking call on it, enforced by a debug assertion).
- **R-UI-9 Read once:** the service reads the trust store, settings and audit index once per change and keeps them in memory (no re-read per request).
- **R-UI-10 Trace slow operations:** the service and the UI log every command, IPC call and network step slower than its threshold (UI: 16 ms on the UI thread; IPC: 100 ms; network: 1 s) with its name and duration only, never content (F-SEC-01).
- **R-UI-11 Load on demand:** drawer panels, the terminal model, the file browser and the Ajustes screen build their state when first opened; fonts, glyph caches and cursor images load once and are reused.
- **R-UI-12 Nothing unused:** before each milestone gate, unused dependencies, features, strings and tokens are removed (D14 audit kept current).
- **R-UI-13 Visible waits:** every action that waits on the other machine, on a person or on the system shows, within 100 ms of the click, what it waits for and on whom ("Esperando o MacBook aceitar"), in the place the action was taken (the device's page for a connection, the panel for a terminal, the card for pairing); it shows the time left whenever the wait has a deadline, counted by the interface from the deadline the service reported; it offers "Cancelar" whenever the wait can be stopped, and stopping it undoes the request at the other end too; the action that started it cannot be sent again while it waits; and it ends in the result or in a failure that names who refused or what did not answer, never a generic code. The interface's own timeout of a waiting command is longer than the service's, so the service's answer is the one shown (R-UI-7). The wait is a polite live region for screen readers, which hear its start, its change of phase and its end, never each second (D46).
- Not applicable to a native LAN app: image formats and lazy image loading for the web, response compression (video and audio are already compressed; control messages are tiny), database indexes, server-side rendering, code splitting.

## Data and architecture

- **Data** (C5): one device identity per machine (Ed25519); a trust store of paired devices with the grants this machine gives each one (empty after pairing), who granted `UNATTENDED`, their last addresses and Wake-on-LAN MACs; the pairing lockout state; machine settings; an append-only audit log. Per-user UI settings live in the user's app data. The UI never reads these files; it asks the service.
- **Processes** (C2): Windows: `swapdesk-service` (LocalSystem, session 0) owns the network, the identity, the trust store, pairing, permissions, the audit log, `SendSAS` and the administrator terminal; it launches `swapdesk-helper --role system` (SYSTEM token in the console session: capture, encode, cursor, input for `UNATTENDED` sessions) and `swapdesk-helper --role user` (user token: input for prompted sessions, terminal, clipboard, files, quick actions); `Swapdesk.exe` (native Win32 shell, the user) is the UI and the viewer (decode, render, key grab, audio playback, the viewer's own file reads and writes). macOS: `swapdesk-daemon` (root LaunchDaemon) owns what the service owns; `SwapdeskAgent.app` runs as an Aqua agent (user) and as a LoginWindow agent (root, legacy plist); `Swapdesk.app` (native AppKit shell) is the UI and the viewer. Both shells sit on one shared, `unsafe`-free crate for UI state, strings (pt-BR, en) and design tokens.
- **Network ownership (D6):** the service/daemon owns every LAN socket in both roles. The viewer's media reaches the UI over local IPC. So the private key never leaves the service, the LAN guard lives in one place, a session survives a helper restart, and on macOS no agent or app touches the LAN (TN3179: daemons are exempt from Local Network privacy; P8 step 6 confirms). Cost: one local IPC hop on the viewer path, measured against B1 in stage 18 (risk R9); if B1 fails through it, the question returns to the owner.
- **Paths never cross into the service:** no command carries a file path to the service/daemon. The UI (viewer side) and the user helper or Aqua agent (host side) open, read and write files with the user's rights and stream bytes over IPC.
- **Trust boundaries:** (1) The LAN, to the service: only pinned keys reach a session, checked again after every handshake; pairing is the one unauthenticated path, on its own endpoint, open only in pairing mode. (2) User processes, to the service/daemon: any process of the session's user can act as the UI (C2.3), so the service grants a UI connection only what the user could do by hand, and admin-only changes need an elevated or authorized connection. (3) The service, to the helpers: the service starts them from the per-machine install folder and checks their PID on the pipe. (4) The remote peer, to the viewer: video is decoded only in the user-level viewer, never in a SYSTEM or root process.
- **Technology:** Rust (stable). Native interface per OS (D18): Win32 + DirectComposition + Direct2D/DirectWrite with `accesskit` and `accesskit_windows` on Windows, AppKit through `objc2` on macOS; the video goes zero-copy from the decoder into a composition swap chain (Windows) or `AVSampleBufferDisplayLayer` (macOS) under the floating toolbar in the same window. Network: QUIC through `quinn` with `rustls` and `ring`, `tokio` in the service/daemon only, `mdns-sd`. Media: Media Foundation and VideoToolbox (H.264), DXGI Desktop Duplication and ScreenCaptureKit, WASAPI loopback and ScreenCaptureKit audio, Opus through libopus (`opus` crate; `opus-rs` if libopus does not build, D16). OS bindings: `windows` and `windows-sys`, the `objc2` family, `libc` on macOS. Own code instead of crates (D14): the wire codec (PROTOCOL.md 9), the PTY (ConPTY / openpty), file pickers, autostart, the trace logger. One terminal-emulation crate for the terminal panel, chosen in stage 20 (D19). Dev only: `proptest`. Build profiles: release with fat LTO and `panic = "abort"` for the UI, helpers and agents; the service/daemon built in its own profile with `panic = "unwind"` so a panic is isolated to its session (D15; Cargo profiles cannot set `panic` per package, research dependencies.md 5.1).

## Threats

Assets: the screen and keyboard of each machine, SYSTEM/root execution on the host, the device keys, the trust store, the clipboard and files.

| STRIDE | Entry point | Threat | Mitigation |
|---|---|---|---|
| S | LAN, pairing | A machine on the LAN (ARP spoof) sits in the middle of a first pairing, or pairs unsolicited | Pairing only when both users opened "Parear" within 2 minutes (D12); its own endpoint, closed otherwise; commitment before reveal and a 6-digit SAS over both keys and the TLS exporter, compared by both users: one guess, 1 in 10^6 (RFC 6189 argument); lockout after 3 failures, written before the nonce goes out |
| S | LAN, session | A device pretends to be a paired one, or resumes a TLS session to skip the key check | TLS 1.3 with the pinned Ed25519 key on both sides; no tickets, no session storage, no 0-RTT; the post-handshake gate looks the key up again before any stream (PROTOCOL.md 2.4) |
| S | LAN, self | The machine is tricked into connecting to itself or to loopback | Own and loopback addresses refused (F-FIND-02) |
| S | Local IPC | Another user's process, or a squatted pipe, talks to the service as the UI or to the UI as the service | Pipe/socket ACLs; first-instance pipes; the service checks the client's session, SID, PID and token; the UI checks the server's PID against the SCM and connects with identification-level impersonation only; on macOS the daemon checks the peer's audit token and code signature (C2) |
| S, E | Local IPC, same user | Any process of the logged-in user drives the UI or the service as that user | Accepted as the user's own power: the service grants a UI connection only what the user could do by hand; prompted input runs with the user's medium-integrity token (D11); admin-only changes need an elevated or authorized connection (D7, D10) |
| T | Disk | A local user edits or pre-creates the trust store to add a key or grant | The service creates the folder itself with owner SYSTEM/root and a protected DACL, moves aside a pre-existing folder with another owner or a reparse point, never follows reparse points; the DACL is what stops tampering (DPAPI machine scope does not: any local user can decrypt, and can likely create, a machine-scope blob) |
| T | LAN | Altered or replayed packets | QUIC/TLS 1.3 integrity; swap and resume tokens single-use, bound to the device, with a 10 s and 60 s life |
| T | Install | A per-user install or a user-writable folder lets a user swap the helper or daemon binaries | A per-machine installer; the service starts helpers only from a folder users cannot write; the macOS daemon checks its bundle owner and signature at start |
| R | Host | A session happens and nobody knows | Append-only audit log owned by the service, session and grant entries kept apart from rate-limited unauthenticated ones; banner during every session; unknown-device alert |
| I | Host screen, clipboard, files | Data leaks to a device that was never accepted | No media, clipboard, file or terminal stream before `SessionGrant`, and only for granted permissions; concealed clipboard content skipped; new devices have no grants |
| I | Another user's data | An unattended session reads the terminal or files of a user who never granted it | D13: that user is asked first |
| I | Device key, logs | User-level malware steals the private key, or secrets leak into logs | The key lives only in the service/daemon (DPAPI machine scope plus the SYSTEM-only DACL; System keychain on macOS); the never-logged list with a log-capture test (F-SEC-01) |
| I | mDNS | Name, OS and fingerprint visible on the LAN | Accepted: no secret in TXT; LAN only |
| D | Pairing, handshakes, sessions | Floods of handshakes, pairing attempts, streams, transfers or audit entries | Global caps on handshakes and unauthenticated connections with QUIC retry and ignore under load; pairing endpoint limited to one bidirectional stream; explicit receive windows and a buffered-bytes budget per connection; no allocation from a peer-declared length; caps on terminals, transfers and chat; rate-limited unauthenticated audit entries |
| E | Protocol parser in the SYSTEM/root service | A malformed message from a paired or unpaired peer runs code | `swapdesk-proto` has no `unsafe`, strict length limits, rejects trailing bytes; video is decoded only in the user-level viewer; fuzzing in stage 29 |
| E | Service from a standard user, file paths | A standard user grants a remote device SYSTEM terminal or unattended access, or makes the service read or write a path as SYSTEM | Admin-only changes need an elevated or authorized connection, enforced by the service (D7); paths never cross into the service |
| E | Malicious host, to the viewer | A host writes files into the viewer machine | Only answers to the viewer's own `FileGet`, only into the folder the viewer's user chose, names validated, size capped |
| E | Admin terminal, quick actions | A SYSTEM shell or Task Manager appears on the user's desktop | The admin PTY runs in session 0 (Windows) or from the daemon (macOS); Task Manager and Activity Monitor start only as the logged-in user |
